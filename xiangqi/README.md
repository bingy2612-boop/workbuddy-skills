# 中国象棋 · 双人对弈 + 新手提示

一个可以和朋友实时联网下的中国象棋，带**推荐出棋**功能——每次提示不仅给走法，还用人话解释为什么这么走，用来带新手入门。

纯前端单文件，没有构建步骤，不需要 `npm install`。

线上体验：https://xiangqi-online-04797.app.workbuddy.host

## 功能

**对局**
- **同屏对坐**：两人一台设备轮流走，点自己的子，棋盘上标出全部合法落点（绿点=空位，虚线圆=可吃子）
- **联机对战**：建房拿 6 位房间号，或直接发邀请链接；执黑一方棋盘自动翻转 180°，字不倒
- 刷新页面自动坐回原位，不丢棋
- 再开一局需要双方都点同意，避免一方手滑清掉棋局

**给新手的三层帮助**
1. **推荐走法**：点击「提示走法」，棋盘上画箭头指出从哪走到哪，同时给出中文记谱（红方「炮八平七」、黑方「马8进7」，符合正式记谱规范）
2. **讲清理由**：例如「吃掉对方一个卒，净赚约 1 个兵的子力」「抢占中路，中线直通对方九宫」「这枚马的可走点从 2 个变成 3 个，位置更灵活」
3. **被吃预警**：每走完一步，如果对方存在白吃你棋子的着法，立刻提示「⚠️ 黑方可以走 车2进3 白吃红方的马」

另外还有形势评估条（以兵为单位量化，如 `+1.5 个兵`）、被将军时状态灯变红、可折叠的「新手必读」规则速览。

## 运行

**同屏对弈**：直接双击 `index.html` 就行，`file://` 下完全可用。

**联机对战**：需要在已登记的域名下运行，云端 SDK 会做来源校验。本地 `file://` 打开时联机入口会提示不可用，同屏模式不受影响。想自建后端，见下面的「后端」。

## 文件

```
index.html        全部逻辑（规则引擎 + 搜索 + 界面 + 联机同步），约 2000 行
sdk.js            云服务浏览器客户端，已内联到本地，不依赖外网 CDN

```

`index.html` 里搜索 `endpoint:` 和 `publishableKey:`（约第 1539 行）换成你自己的配置。

## 规则引擎

棋盘用 90 字符串表示，`rheakaehr...` 小写为黑、大写为红。

走子生成用标准 **perft** 校验过，初始局面逐层节点数：

| 深度 | 节点数 |
|---|---|
| 1 | 44 |
| 2 | 1,920 |
| 3 | 79,666 |

与国家象棋公开基准完全一致，说明车马炮士象将的蹩马腿、塞象眼、炮架隔子、兵过河横走、九宫限制、飞将（将帅照面）等规则均无误。另外单独验证了飞将判负、一步杀判定、红黑镜像对称。

## 搜索

Alpha-Beta 迭代加深 + 静态搜索（quiescence），默认深度 4，开局约 400ms。加了静态搜索是为了避免「算到一半就停」导致的昏招——到了搜索边界仍把吃子走完再评估。

评估用的是子力价值 + 位置分（过河兵、马炮活跃度、车占中路等）。自对弈抽检 40 步，棋路正常，没有乱送子的情况。

搜索是同步计算，点提示时有极短停顿属正常。想更强或更快，改 `index.html` 里 `searchRoot(before, red, 4)` 的深度参数（5 更强但明显变慢，3 更快但棋力下降）。

## 联机架构

没有长连接，因为所用云服务只提供 REST，同步靠轮询：

- **轮询** 850ms 拉一次房间状态，**心跳** 9s 摸一次在线状态，对手超过 30s 没心跳才显示「暂时离开」
- **`chess_rooms`** 存棋局（board / turn / moves / move_count / status），公开只读
- **`chess_seats`** 存座位令牌，前端完全读不到别人的令牌，RLS 全关闭
- 所有写操作都走 `SECURITY DEFINER` 函数，服务端依次校验三件事：**你是不是这局的人 → 是不是该你走 → 步数对不对**

校验失败的错误码：

| 错误 | 含义 |
|---|---|
| `room_not_found` | 房间号不存在 |
| `room_full` | 房间已有两人 |
| `not_in_room` | 令牌无效，不是这局的人 |
| `not_your_turn` | 没轮到你 |
| `stale_move` | 步数不连续，说明你看到的是旧局面 |
| `not_playing` | 对局已结束 |

`move_count` 的连续性是防重复提交的关键：客户端提交 `p_count = 当前步数 + 1`，服务端比对不符就拒绝，所以同一方连点两次不会走两步。

## 后端

`sql/schema.sql` 里是完整的建表、RLS、以及六个函数（`chess_create` / `chess_join` / `chess_move` / `chess_finish` / `chess_restart` / `chess_ping`）。在 PostgreSQL（或兼容的云数据库）里执行一遍即可。

两个表都开了 RLS：`chess_rooms` 只给 `SELECT`，`chess_seats` 一律不给，写权限全部收在函数内部。

## 已知取舍

- **不是帧级同步**：对手落子到你屏幕上出现，最差约 1 秒。朋友之间下棋够用，不适合快棋。
- **规则跑在客户端**：两边各算各的，服务端只校验轮次和步数，不重算棋盘合法性。朋友之间互信的前提够用；要防改客户端作弊，得让服务端再做一次走子校验。
- **联机不能悔棋**，点了会提示。悔棋需要双方协商一致才有意义，做成单人按钮容易扯皮。
- **没有内置 AI 对手**。现在只有「提示」和「按提示走」，本质是给两个人用的教练，不是人机对战。

## 实现备注

- 中文记谱：红方纵线自右向左 1-9（`col → 9-col`），黑方自左向右（`col+1`）；车炮兵帅的进退写步数，马相士的进退写目标纵线
- 棋盘是 SVG，`viewBox` 固定，靠 CSS 缩放适配窄屏；格子点击热区用透明矩形覆盖，避免线和子的 pointer 事件互相干扰
- 全局加了 `[hidden]{display:none!important}`，否则 `display:flex` 会盖掉 `hidden` 属性的默认样式
